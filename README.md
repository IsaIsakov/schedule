## Быстрый запуск

Откройте `dist/index.html` в браузере — сайт работает без установки и без интернета. Интернет нужен только для перехода к исходному занятию в CELCAT.

Для локального веб-сервера установите Node.js 22 или новее и выполните:

```sh
npm start
```

Откройте `http://127.0.0.1:4173`. Внешних пакетов нет, `npm install` не нужен.

## Область проверки

Отдельные лекции исключены по пожеланию пользователя. Occupational Safety Management включён, потому что его категория — **Lecture + Tutorials**. По каждому предмету выбрана одна группа; совместное занятие с другой группой не считается сменой группы. Запись в университетские группы сайт не выполняет.

Это статические копии, а не синхронизация с CELCAT. Изменения после индивидуальной даты проверки автоматически не попадут на сайт. Добавление Мансура 01.10.2026 не означает повторной проверки других трёх расписаний. Последняя доступная неделя во всех четырёх календарях — 25–31 января; сведения об экзаменах или занятиях за пределами доступного периода не подтверждены. Пустая неделя означает отсутствие опубликованных занятий выбранных групп, а не официальное объявление каникул. Для Мансура это утверждение касается только шести найденных предметов.

## Структура репозитория

```text
dist/                 Готовый сайт для размещения
  index.html
  app.css
  app.js
  data.js             Данные для браузера, без сетевых запросов
data/
  catalog.json        37 определений занятий с исходным текстом
  selections.json     Выбранные группы и явные списки дат
  metadata.json       Источники проверки и контрольные суммы
  audit.json          Воспроизводимый отчёт
  ui-checks.json      Результат проверки интерфейса
  mansur-selection-review.json  Область проверки и подбор групп Мансура
scripts/
  verify.mjs          Проверка и сборка данных
  serve.mjs           Локальный сервер
package.json
```

Редактирование интерфейса не требует сборки. Для обновления данных измените `catalog.json` и `selections.json`, заново сверив занятия с CELCAT. Контрольные суммы в `metadata.json` должны быть получены из нового независимого извлечения источника, а не заменены автоматически ради прохождения проверки. Затем:

```sh
npm run build
npm test
```

## Размещение

Загрузите содержимое `dist/` на любой статический хостинг. Все пути относительные, поэтому сайт работает и в подпапке репозитория. Никаких ключей, базы данных, сервера приложения или платных сервисов не требуется.

Для GitHub Pages с публикацией из ветки скопируйте **содержимое** `dist/` в корень публикуемой ветки или в папку `docs/`, затем выберите эту папку в настройках Pages. Не публикуйте страницу предпросмотра `127.0.0.1`: это адрес только локального компьютера.

### Railway

Для Railway загрузите в репозиторий **всё содержимое архива**, включая `package.json`, `scripts/`, `data/` и `dist/`. В корне выбранного сервиса должен находиться `package.json`.

- **Start Command:** `npm start`
- **Build Command:** `npm run build` (проверка и подготовка данных)
- **Healthcheck Path:** `/`
- **Root Directory:** корень репозитория, если архив распакован туда.

Сервер слушает `0.0.0.0` и берёт порт из переменной `PORT`, которую задаёт Railway. Без неё локальный порт — `4173`. Если у публичного домена вручную задан Target Port, он должен совпадать с портом из строки `Server listening on 0.0.0.0:...` в журнале запуска.

В версии 1.0.1 исправлен адрес прослушивания: прежний `127.0.0.1` работал локально, но не позволял прокси Railway подключиться к приложению. После обновления репозитория выполните новый деплой последнего коммита.

[Документация Railway об ошибке Application Failed to Respond](https://docs.railway.com/networking/troubleshooting/application-failed-to-respond).
